```mermaid
    class Producto {
        <<abstract>>
        +id: Int
        +nombre: String
        +marca: String
        +precio: Double
        +stock: Int
        +deporte: Deporte
        +hayStock(cantidad: Int) Boolean
        +reducirStock(cantidad: Int)
    }

    class Calzado {
        +talla: Int
    }

        +talla: String
        +material: String
    }

    class Equipamiento {
        +pesoKg: Double
    }

    class Deporte {
        <<enumeration>>
        FUTBOL
        BASQUET
        TENIS
        RUNNING
        NATACION
    }

    class Cliente {
        +id: Int
        +nombre: String
        +email: String
        +carrito: Carrito
    }

    class Carrito {
        -items: MutableList~ItemCarrito~
        +agregar(producto: Producto, cantidad: Int)
        +quitar(producto: Producto)
        +total() Double
        +vaciar()
    }

    class ItemCarrito {
        +producto: Producto
        +cantidad: Int
        +subtotal() Double
    }

    class Pedido {
        +id: Int
        +cliente: Cliente
        +items: List~ItemCarrito~
        +fecha: LocalDate
        +estado: EstadoPedido
        +total() Double
        +cambiarEstado(nuevo: EstadoPedido)
    }

    class EstadoPedido {
        <<enumeration>>
        PENDIENTE
        PAGADO
        ENVIADO
        ENTREGADO
        CANCELADO
    }

    Producto <|-- Calzado
    Producto <|-- Ropa
    Producto <|-- Equipamiento
    Producto --> Deporte
    Tienda "1" o-- "*" Producto : inventario
    Tienda "1" o-- "*" Pedido : pedidos
    Cliente "1" *-- "1" Carrito
    Carrito "1" *-- "*" ItemCarrito
    ItemCarrito "*" --> "1" Producto
    Pedido "*" --> "1" Cliente
    Pedido "1" *-- "*" ItemCarrito
    Pedido --> EstadoPedido
```

Así se pasa a Kotlin:
- Producto es una abstract class y de ella heredan Calzado, Ropa y Equipamiento.
- Deporte y EstadoPedido son enum class.
- ItemCarrito queda bien como data class.

Problemas que tenía el diagrama anterior:
- Los pedidos se iban a vaciar. El Pedido apuntaba a los mismos items del carrito, así que al vaciar el carrito el pedido quedaba sin items. Ahora el pedido guarda una copia de los items y su propio total.
- Faltaba lo que pasa al comprar. No decía quién revisa y descuenta el stock ni quién vacía el carrito. Ahora todo eso lo hace Tienda.confirmarCompra(), y devuelve null si no se puede comprar.
- Las dos pantallas no tenían cómo compartir datos. Tienda ahora es un object de Kotlin, así el catálogo y el carrito usan el mismo inventario y el mismo carrito.
- El carrito no controlaba el stock. agregar() ahora devuelve false si ya llegaste al stock disponible.
- La herencia no servía para nada. Agregué detalle() como método abstracto: cada tipo de producto muestra su dato propio (talla o peso) y la pantalla no necesita saber qué tipo es.

Lo que quité por no usarse en 2 pantallas: Cliente, porque no hay login, y EstadoPedido, porque ninguna pantalla cambia el estado de un pedido. Si tu docente pide que estén, se pueden volver a agregar.

Las 2 pantallas alcanzan para todo:
1. Catálogo: filtro por deporte, lista de productos, botón "Agregar" y acceso al carrito.
2. Carrito: botones + y −, el total y "Confirmar compra", que muestra un diálogo con el número de pedido.

Reglas de negocio (contenido del .md):
- Tienda es un object de Kotlin (singleton) para que ambas pantallas compartan el mismo inventario y carrito.
- Producto es abstract class; detalle() es abstracto y cada subclase devuelve su dato propio ("Talla 42", "Talla M", "1.5 kg"). La UI lo muestra sin saber el tipo concreto.
- Carrito.agregar(producto): suma 1 unidad (crea el item si no existe). Devuelve false si la cantidad en el carrito ya alcanzó el stock del producto.
- Carrito.quitar(producto): resta 1 unidad; si llega a 0, elimina el item.
- Tienda.productosPorDeporte(null) devuelve todo el inventario.
- Tienda.confirmarCompra():
  1. Si el carrito está vacío o algún producto no tiene stock suficiente, devuelve null.
  2. Reduce el stock de cada producto.
  3. Crea el Pedido con una copia de los items y el total calculado en ese momento (id = pedidos.size + 1, fecha = hoy).
  4. Agrega el pedido a pedidos, vacía el carrito y devuelve el pedido.

### 1. Catálogo (CatalogoScreen)
